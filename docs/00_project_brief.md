# 推し活OS 企画提案書(承認済み)

> 工程0の成果物。2026-07-29 にオーナー承認済み。
> 本ドキュメントはプロジェクト全体の前提となる。

## サービスコンセプト

**「推し活に必要なすべてを、スマホ1つで。」**

推し活に必要な情報・予定・遠征準備・持ち物・グッズ・思い出を、スマートフォン1つでまとめて管理できるWebサービス。
ライブ・イベント当日に「必ず開きたくなる」実用ツールを目指す。

## 基本戦略

- 表側の見せ方は King & Prince ファン向けに深く特化する
- 裏側のシステムは複数の推し(アイドル・アーティスト・俳優・舞台・スポーツ観戦など)に対応できる汎用設計にする
- 狭いターゲットから開始し、利用実績を作ってから横展開する

## 解決するユーザーの悩み

1. **情報がバラバラ** — 予定・持ち物・チケット・ホテルが複数アプリに散らばる
2. **期限を忘れる** — FC申込期限・支払期限・キャンセル期限など「落とせない期限」が多い
3. **遠征の準備が大変** — 交通・宿泊・予算・持ち物を毎回ゼロから考える負担
4. **当日にあわてる** — 当日確認したい情報が複数アプリに分散
5. **思い出が流れる** — 写真やSNSに埋もれて見返しにくい

## MVP範囲(決定)

**入れる機能(8つ)**
1. ユーザー登録・ログイン
2. 推し登録(King & Prince を標準候補として表示。内部は汎用設計)
3. 推し活カレンダー(カテゴリー別色分け・期限強調)
4. 遠征プランナー(交通・宿泊・予算の自動集計)
5. 持ち物チェックリスト(標準テンプレート+自由編集・イベント別保存)
6. ライブ当日モード(1画面集約・未完了警告)※中心機能
7. アフィリエイトリンク管理機能(管理画面・広告表記つき)
8. スマートフォン対応(スマホファースト)

**入れない機能(将来追加。ただしデータ設計で拡張余地を確保する)**
- グッズ管理 / 推しノート / 推し友共有 / AIコンシェルジュ
- プッシュ通知 / 月額課金 / 天気の自動取得(MVPは手動または外部リンク)

## 収益導線

- 第1段階:アフィリエイト(宿泊・交通・持ち物・CD/雑誌)。「広告」「PR」表記必須。ASP非固定・管理画面で差し替え可能
- 第2段階:月額課金(無料=推し1人・基本機能/有料=複数推し・AI拡大・共有・広告削減など)

## 著作権・肖像権の方針(決定)

1. 公式画像・ロゴ・楽曲・歌詞・映像を運営側が掲載しない
2. メンバーカラーは「テーマカラー」としてユーザーが選択する形にする
3. ユーザー登録画像は本人のみ閲覧・規約で責任範囲を明記
4. サービス名にグループ名を含めず「公式」「公認」を使わない
5. 公開情報を扱う場合は出典を明示できる設計にする

## 主要リスク

| リスク | 対策 |
|---|---|
| 当日モードの信頼性(遅い・開けない) | シンプル構成・表示を軽く |
| 入力の手間で離脱 | テンプレート・初期値の充実、入力最小化 |
| 公式アプリとの誤認 | 権利方針の徹底、規約・表記の整備 |
| 機能の作りすぎ | MVP範囲の厳守 |
| 個人情報(予定・宿泊先) | 本人のみ閲覧が原則。共有は選択制(将来) |
| アフィリエイト審査(推定) | ASP非依存のリンク管理設計 |

## 開発の進め方

1. ターゲットユーザーと課題の整理 → 2. 競合との差別化整理 → 3. MVP要件定義 → 4. 機能一覧 → 5. 画面一覧 → 6. ユーザー導線 → 7. ワイヤーフレーム → 8. UIデザイン → 9. DB設計 → 10. 技術構成 → 11. 実装 → 12. テスト → 13. デバッグ → 14. 公開前チェック

各工程完了ごとにオーナーへ報告し、承認を得てから次工程へ進む。
