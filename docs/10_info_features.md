# 情報収集まわりの3機能(設計と方針)

「ウェブの情報を集めて反映できないか」という要望に対し、**著作権・利用規約の面で安全な範囲**で
「情報を見逃さない」を実現する3機能を追加した。

## 大前提:他サイトの内容は取り込まない

本アプリは、外部サイトの記事・見出し・画像を取得して自分のページに載せることをしない。

理由:

1. プロジェクト方針(docs/00 の著作権方針)で「公式の文章を無断で転載しない」と定めている
2. 日本では、見出しのような短い表現でも、組織的に複製・利用する行為が不法行為と判断された裁判例がある(2005年・知財高裁。**著作物にあたらない=自由に使える、ではない**)
3. 収集したデータは元サイトの変更で簡単に壊れる。期限管理アプリで誤った日付を表示することは、機能の目的そのものを損なう
4. 他人の情報を集めたページで広告収入を得る形は、ASP(広告サービス)の規約で禁止されることが多い

そのうえで、以下の3つを実装した。

## 機能1:情報チェック(リンク集)`/sources`

- ユーザーが「いつも確認しているサイト」を自分で登録し、一覧からワンタップで開ける
- **内容はコピーせず、リンク(入口)だけを扱う**
- 各リンクの「最終チェック日」を記録し、7日以上たつと警告色で表示 → 見逃しに気づける
- 登録内容はユーザーの端末内のみに保存
- 全ユーザー共通で出したいリンクは `web/src/data/affiliate-links.json` と同様に
  `web/src/data/info-sources.json` で配布できる(初期状態は空。URLは運営者が確認したものを設定する)

## 機能2:貼り付け一括登録 `/events/import`

ユーザーが**自分で見つけた文章**を貼り付けると、日付を読み取って予定候補を作る。
外部サイトへのアクセスは一切行わない(解析するのは貼り付けられた文字列のみ)。

読み取れるもの:

| 種類 | 例 |
|---|---|
| 日付 | `2026年8月10日` `2026/8/10` `2026-08-10` `8/10` `8月10日` |
| 時刻 | `開場16:00 開演18:00` `18時30分` |
| カテゴリー | 締切・支払・当落・ライブ・舞台・発売などのキーワードから自動判定 |

安全側に倒した設計:

- **日付のない行は無視する**(推測で予定を作らない)
- 存在しない日付(2月30日など)は読み取らない
- 曜日「(土)」が書かれていれば、それに合う年を選ぶ(来年の日程表を貼ったときの年の取り違えを防ぐ)
- 登録前に必ず一覧で確認・カテゴリー修正・個別除外ができる
- 「読み取りは自動判定のため、期限は必ず元の情報で確認してください」と画面に明記

## 機能3:天気の自動表示(ライブ当日モード)

- 予定に「会場のある都市」(全国15都市)を設定すると、当日モードに天気を自動表示
- 気象データは公共性の高い情報を提供する Open-Meteo を利用(APIキー不要・ブラウザから直接取得)
- 表示内容:天気・最高/最低気温・降水確率・「雨具があると安心です」の注意
- 予報が出せるのは約2週間前から。それ以前は「まだ予報が出ていません」と表示

**当日モードを壊さないための設計(最重要)**

天気は「取得できないことがある前提」で作っている。通信できない・APIが応答しない・
想定外の応答が返る、いずれの場合も天気欄だけがメッセージ表示に切り替わり、
座席・持ち物・交通・宿泊などの当日情報は必ず表示される。
外部の天気サイトへのリンクも常に残している。
