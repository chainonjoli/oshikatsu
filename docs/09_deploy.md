# 公開手順(デプロイガイド)

このアプリをインターネット上に公開して、スマホから誰でも使えるようにする手順です。
専門知識がなくても進められるよう、画面操作中心で説明します。

## 前提:公開には「ホスティングサービス」のアカウントが必要

アプリを24時間動かすサーバーはご自身のアカウントで借りる必要があります。
おすすめは **Render**(レンダー)です。理由:

- GitHub アカウントでそのまま登録できる
- このリポジトリに設定ファイル(`render.yaml`)を用意済みなので、ほぼクリックだけで公開できる
- HTTPS(鍵マーク付きの安全な通信)が自動で付く

料金の目安(2026年時点・**推定**。申込画面で最新価格を確認してください):
- Web サービス Starter プラン:月 $7 前後
- 永続ディスク 1GB:月 $0.25 前後
- ※無料プランはスリープ(アクセスがないと停止)し、かつ**ディスクが使えずデータが消える**ため、本アプリでは有料プランを推奨します

## 手順(Render の場合・所要 15分程度)

1. **PR をマージする**
   GitHub の PR(#1)ページで「Merge pull request」を押し、`main` ブランチに取り込みます。

2. **Render に登録**
   https://render.com を開き、「Sign Up」→「GitHub でログイン」を選びます。

3. **リポジトリを接続して Blueprint を実行**
   ダッシュボードで「New +」→「Blueprint」→ `chainonjoli/oshikatsu` を選択 → 「Apply」。
   `render.yaml` が自動で読み込まれ、アプリと永続ディスクが作成されます。

4. **ビルド完了を待つ(5〜10分)**
   完了すると `https://oshikatsu-os-xxxx.onrender.com` のようなURLが発行されます。
   このURLをスマホで開けば、どこからでも使えます。

5. **最初のアカウントを自分で登録する**
   ⚠️ 重要:**最初に登録したユーザーが管理者**になります。
   URLが発行されたら、他の人に知らせる前に必ずご自身で最初の登録を済ませてください。
   (管理者は 設定 → 運営メニュー からアフィリエイトリンクを管理できます)

## ほかの選択肢(推定)

| サービス | 特徴 |
|---|---|
| Railway | 使った分だけの従量課金。ボリューム(永続ディスク)をアプリの `/app/data` にマウントする |
| Fly.io | 無料枠あり。設定はやや技術者向け |
| VPS(さくら等) | 自由度最大だがサーバー管理の知識が必要 |

いずれも Docker 対応なので、用意済みの `web/Dockerfile` がそのまま使えます。
※ Vercel などのサーバーレス環境は、SQLite のファイル保存ができないため**そのままでは動きません**(PostgreSQL への移行が必要)。

## 公開前に必ず確認すること

`docs/08_test_and_release.md` のチェックリストのうち、特に以下は「友人・知人でのテスト公開」を超えて広く告知する前に済ませてください。

1. **利用規約・プライバシーポリシーの掲載**(ユーザーがメールアドレスや予定を登録するため)
2. **問い合わせ先の明示**(パスワードを忘れた人への対応窓口。再設定メール機能は未実装)
3. **正式なサービス名の決定**(現在は仮称)
4. **データのバックアップ**(Render のディスクスナップショット、または `/app/data/app.db` の定期コピー)

## 運用開始後の更新方法

`main` ブランチに変更をプッシュ(またはPRをマージ)すると、Render が自動で再ビルド・再デプロイします。データは永続ディスクにあるので消えません。
