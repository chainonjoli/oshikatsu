# 工程1:ターゲットユーザーと課題の整理

> 注:本ドキュメントのペルソナ・行動フロー・利用シーンは、公開されている一般的なファン行動の傾向にもとづく **推定** を含む。実ユーザーへのヒアリングで検証されたものではない。リリース後に実際の利用データ・ユーザーの声で見直す前提とする。

## 1. ターゲットの全体像

**初期ターゲット:King & Prince を応援している女性ファン**

| 条件 | 内容 |
|---|---|
| デバイス | スマートフォン中心。PC操作は得意でない人も多い |
| 行動 | ライブ・舞台へ参加する。遠征することがある |
| 悩み | 予定・申込期限を忘れたくない。情報が複数アプリに分散 |
| 交友 | 推し友と一緒に行動することがある |
| 所有 | グッズを多く持っている |

## 2. ペルソナ(推定)

### メインペルソナ:あかりさん(28歳・会社員)

- **プロフィール**:事務職。首都圏在住ではなく地方都市在住。ファン歴3年以上、ファンクラブ会員
- **推し活の頻度**:年2〜4回ライブ・舞台に参加。年1〜2回は新幹線や飛行機で遠征
- **デジタル環境**:iPhone。よく使うのはLINE・X(旧Twitter)・カレンダーアプリ・メモアプリ。PCはほぼ使わない
- **現在の管理方法**:
  - 予定 → スマホの標準カレンダー
  - 持ち物 → メモアプリに毎回書き直す
  - チケット情報 → 当落メールを検索して探す
  - ホテル・新幹線 → 予約サイトの確認メール
  - 推し友との約束 → LINEのトーク履歴をさかのぼる
- **痛み**:
  - 「あの情報どこだっけ?」と当日にメールやLINEを検索する
  - 支払期限を1度忘れかけて、それ以来ずっと不安
  - 遠征のたびに持ち物リストをゼロから書いている
- **求めるもの**:全部が1か所にまとまっていて、当日に迷わないこと

### サブペルソナ:みゆさん(20歳・大学生)

- **プロフィール**:ファン歴1〜2年。アルバイト収入の範囲で推し活
- **推し活の頻度**:年1〜2回。遠征は夜行バス+安いホテル
- **痛み**:
  - 予算オーバーが怖い。交通費・宿泊費・グッズ代の合計が見えない
  - 初めての会場・初めての遠征で、何を準備すればいいか分からない
- **求めるもの**:予算の見える化と、準備の「お手本」(テンプレート)

### 参考ペルソナ:ともこさん(45歳・パート)

- **プロフィール**:ファン歴が長く、グッズ・雑誌・円盤を多数所有
- **痛み**:発売日が多くて把握しきれない。同じ雑誌を2冊買ってしまったことがある
- **求めるもの**:発売日カレンダーと(将来の)グッズ管理
- ※グッズ管理はMVP対象外だが、この層の存在は将来機能の優先度判断に使う

## 3. 推し活の行動フローと痛みの対応表

ライブ参加を軸にした一連の流れ。★が本サービスの介入ポイント。

| フェーズ | ユーザーの行動 | 痛み | MVPでの解決 |
|---|---|---|---|
| ① 情報キャッチ | ツアー発表・発売情報を知る | 情報源がバラバラ | ★カレンダーに自分で登録(カテゴリー分け) |
| ② 申込 | FC抽選に申し込む | 申込期限を忘れる | ★期限カテゴリーの強調表示 |
| ③ 当落・支払 | 当落確認、期限内に支払う | 支払期限が最重要かつ忘れやすい | ★支払期限カテゴリー+ホームで直近期限を警告 |
| ④ 遠征計画 | 交通・宿泊を予約、予算を組む | 毎回ゼロから。総額が見えない | ★遠征プランナー(予算自動集計) |
| ⑤ 直前準備 | 持ち物をそろえる | リストを毎回作り直す。買い忘れ | ★チェックリスト(テンプレート+イベント別保存)/未所持品にアフィリエイト導線 |
| ⑥ 当日 | 移動・集合・入場・観劇 | 情報が分散し、あわてる | ★★ライブ当日モード(1画面集約・未完了警告) |
| ⑦ 事後 | 思い出を残す、精算する | 記録が流れる。精算が面倒 | (MVP外:推しノート・推し友共有で将来対応) |

**設計上の含意**:③⑥が最も痛みが強く、③は「ホームでの期限警告」、⑥は「ライブ当日モード」として最優先で作り込む。

## 4. 利用シーン別の要求

### シーンA:平日夜、ベッドの上で(日常利用)
- 片手・縦持ち・数分の利用
- 次のイベントまでのカウントダウン、直近の期限確認
- → ホーム画面は「開いた瞬間に今の状況が分かる」こと

### シーンB:遠征の1〜2週間前(準備利用)
- 遠征プランの作成、持ち物の確認・買い足し
- → テンプレートで入力の手間を最小化。合計予算が自動で見える

### シーンC:ライブ当日(最重要利用)
- 移動中・会場周辺で、電波が不安定な場合もある(推定)
- 確認したいのは:開演時間・座席・持ち物・集合・交通・宿泊・天気
- → 当日モードは軽く・速く・1画面。読み込み後は再通信なしで見られる構成を目指す

## 5. ユーザー課題の優先順位(MVPの判断基準)

| 優先度 | 課題 | 対応機能 |
|---|---|---|
| 1 | 当日に情報が分散してあわてる | ライブ当日モード |
| 2 | 期限を忘れる | カレンダー+期限警告 |
| 3 | 遠征準備の負担・予算不安 | 遠征プランナー |
| 4 | 持ち物の作り直し・忘れ物 | 持ち物チェックリスト |
| 5 | 発売日の把握 | カレンダー(発売カテゴリー) |
| 6以降 | グッズ重複購入・思い出・共有・相談 | 将来機能 |

## 6. 検証したい仮説(リリース後)

1. ライブ当日にアクティブ率が跳ね上がる(当日モードが使われている証拠)
2. 期限カテゴリーの予定登録が多い(期限管理ニーズの証拠)
3. 持ち物テンプレートの利用率が高い(テンプレート価値の証拠)
4. 遠征プランナーからのアフィリエイトタップが発生する(収益導線の証拠)
